## 2. The contradiction

§23, §24, §25 and §33 say the galaxy and voice are not part of v0.1. RK has decided that a limited, truthful form of both should ship in the **v0.1 Beta**, as a Beta, with the finished dashboard still arriving in Phase 7. An ADR cannot widen the Master Context (ADR-0001 D3). Therefore an MCA is required.

## 3. Current text (committed)

§23: "Do not build the cinematic 3D galaxy yet. Start with a functional dashboard. ... The 3D Knowledge Galaxy belongs to a later phase."
§24: heading "Knowledge Galaxy — Later"; "The galaxy is a visualization layer. It must not become the governance layer."

## 4. Proposed new text

Terms used below:

- **v0.1 Beta**: the Beta release of JARVIS (target 2026-11-29). It is a Beta of the control plane and its interaction surfaces. It is not "v0.1 complete": §31 and §37 still apply and are not met by the Beta.
- **Beta dashboard**: the functional minimum shipped in the Beta.
- **Phase 7 dashboard**: the finished functional dashboard of the product.

### 4.1 §23 (replace two lines, then append)

Replace the first line "Do not build the cinematic 3D galaxy yet." with: "Do not build the full cinematic 3D galaxy yet. The v0.1 Beta sub-context below defines a limited, truthful Beta subset."

Replace the last line "The 3D Knowledge Galaxy belongs to a later phase." with: "The full 3D Knowledge Galaxy belongs to later phases."

Then append:

```text
v0.1 Beta sub-context (MCA-002).
The v0.1 Beta ships a Beta dashboard. It is the functional minimum, not an
intentionally incomplete one: system status and health, projects, tasks,
notes, results, recent activity, audit and backup status, errors, and
blocked, deferred and cancelled work (shown as states, not necessarily as
separate views), all read from real records. It adds a
live status ring and a read-only galaxy (section 24). The finished
functional dashboard, with the full panel list and the controls above
(Pause, Resume, Stop), is completed in Phase 7. Beta dashboard work is a
subset of Phase 7 and is replaced or extended by it, never contradicted.
Every Beta interface surface is read from the control plane's records and
holds no authority (section 26).
```

### 4.2 §24 (replace the heading, add one sentence, then append)

Replace the heading "Knowledge Galaxy — Later" with: "Knowledge Galaxy — Full Version Later".

Add as the first sentence of the section: "The full Knowledge Galaxy belongs to later phases."

Then append:

```text
v0.1 Beta sub-context (MCA-002).
The v0.1 Beta may ship a read-only galaxy. Every LIVE node and every
displayed relationship must map to real source data. Future capabilities may
appear only as nodes clearly labelled PREVIEW, DEFERRED or BLOCKED, and are
never counted as records or activity. No fabricated telemetry or activity.
The typed relationships above and Memory, Research and Evidence nodes remain
later. The galaxy is a visualization layer and never a governance layer.
```

### 4.3 §25 (replace the heading and the first line, then append)

Replace the heading "Voice — Later" with: "Voice — Full Version Later".

Replace the first line "Voice is not part of v0.1." with: "Full voice is not part of v0.1. The v0.1 Beta sub-context below defines the Beta subset."

Then append:

```text
v0.1 Beta sub-context (MCA-002).
The v0.1 Beta may ship push-to-talk voice: local speech input and local
speech output, on a separate interaction surface that holds no authority.

policy path as the CLI. Voice identity grants no authority. The microphone is
open only while the user holds push-to-talk. Still later, and excluded from
the Beta: wake word, always-listening, barge-in, interruption, mobile
support, any external communication, phone calling, and any cloud speech.
```

## 5. Rationale

1. RK decided the Beta should show the JARVIS identity: ring and galaxy. The galaxy and ring are display-only over records JARVIS already holds, so they add no authority.
2. Push-to-talk voice is an input and output surface. It adds no privilege because it must pass the same policy path.
3. Calling it a Beta sub-context keeps the Master Context honest: v0.1 is still not complete, and the finished dashboard stays Phase 7.
4. The security principles of §26 do not change.

## 6. Security and architectural impact

- Two new interaction surfaces. Each needs its own ADR before any code (ADR-0010 section 6: "Voice, UI or model access to any of this ... needs its own ADR"). ADR-0011 and ADR-0012 are proposed beside this record.
- Network use (a localhost UI server) and speech runtimes sit outside the control plane (`jarvis/`), which keeps ADR-0006 and X-13 intact. This record does not itself permit any network use, install or microphone use.
- No change to L0-L5, to the forbidden actions, to §26, or to policy.

## 7. Compatibility impact

- **Unchanged:** §26, §27, §31, §32, §37, §39. The Beta does not meet §31 and must say so (Beta plan B-13).
- **Still excluded from the Beta and from this amendment:** wake word, always-listening, barge-in, mobile, phone calling, external communication, cloud speech, LAN access, autonomous execution, unrestricted computer control, any model holding authority.
- **If rejected:** the Master Context stands as written. The Beta ships without ring, galaxy and voice. The other items of the Beta plan are unaffected.
